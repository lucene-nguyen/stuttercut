# CLAUDE.md — StutterCut

Guidance for Claude Code working in this repository. Read this first, then the design documents linked below before changing code.

## What this project is

StutterCut is a **local web app** that detects stutters, filler words, long pauses and retakes in short Vietnamese videos (≤ 3 minutes), lets a person review the suggested cuts, then renders a clean video.

- Runs on one machine. Develop on **Windows**, run on **macOS (Apple Silicon, 16 GB RAM)**. Same codebase for both.
- The LLM review runs on a local model (Ollama) by default. With the opt-in Anthropic provider, only **transcript text** leaves the machine. Never send audio or video anywhere.
- Keep it simple: 3 UI screens (Upload & jobs, Review & render, Diagnostics), no settings screen, no accounts, no cloud services.

## Architecture in one paragraph

Browser UI (React) talks only to the **API server** (FastAPI): REST + SSE progress + HTTP Range for video. The API server owns the **job queue** (1 job at a time) and the **watchdog**. A separate **worker process** runs the pipeline: extract audio (FFmpeg) → transcribe (CrisperWhisper, verbatim, word timestamps) → detect (rule engine + LLM for retakes) → render (FFmpeg) or export FCP XML. State lives in **SQLite** (jobs, words, cuts, spans); media and JSON Lines logs live in folders resolved by `platformdirs`.

## Tech stack

- **Backend:** Python 3.11+, FastAPI, Uvicorn, `multiprocessing`, SQLite, `psutil`, `platformdirs`
- **ML:** CrisperWhisper 2.0 large, verbatim mode, via PyTorch (`mps` → `cuda` → `cpu`; `turbo` when the RAM pre-flight fails). Cut candidates = verbatim vs intended diff + VAD uncovered segments + pause rules ([ADR 0002](docs/adr/0002-crisperwhisper-verbatim-asr.md))
- **LLM review:** Ollama + `qwen3:8b` locally (default), or the Anthropic Messages API (opt-in, text only)
- **Media:** FFmpeg (`h264_videotoolbox` → `h264_nvenc` → `libx264`)
- **Frontend:** React + TypeScript (strict), Vite
- **Quality:** ruff, mypy, pytest, hypothesis, vitest, Playwright, `@axe-core/playwright`, pre-commit, GitHub Actions

## Common commands

```bash
# setup
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -e "backend[dev]"
pre-commit install                                   # hooks use the active venv's ruff/mypy
cp .env.example .env                                 # fill in LLM_API_KEY
cd frontend && npm install

# run (from the repo root, venv active)
uvicorn stuttercut.api.main:app --reload             # API on 127.0.0.1:8000 (worker comes later)
pip install -e "backend[dev,asr]"                    # real transcriber (CrisperWhisper + torch); CUDA: docs/guides/setup-windows.md
python -m stuttercut.worker.cli "<video>"            # one job in-process: timings, word + cut counts, peak RAM (no text)
python -m stuttercut.worker.cli render latest --approve sure --format both
                                                     # <name>_clean.mp4 / .xml in STUTTERCUT_OUTPUT_DIR (default Videos/StutterCut)
# LLM review: install Ollama, `ollama pull qwen3:8b`, set STUTTERCUT_LLM_ENABLED=true (docs/guides/local-llm.md);
#   the CLI then prints tiers, tokens, Ollama RAM/VRAM and the ASR reload cost. Anthropic: PROVIDER=anthropic + LLM_API_KEY
cd frontend && npm run dev                           # UI on 127.0.0.1:5173, proxies /api

# quality (Python tool config lives in the root pyproject.toml)
ruff check . && ruff format --check .
mypy backend                                         # strict on backend/stuttercut
pytest                                               # all tests except golden (fake transcriber)
pytest --cov=stuttercut.rules --cov-fail-under=80    # rule engine coverage gate (as in CI)
pytest -m golden                                     # accuracy eval, real model (slow); exits 5 until golden tests exist
pre-commit run --all-files

# ASR spike eval (LEARNING-205), see docs/guides/running-eval.md
pip install -e "backend[dev,eval]"
python -m eval.convert_audacity "$STUTTERCUT_DATA_DIR/audacity" eval/labels
python -m eval.run_spike                             # needs STUTTERCUT_DATA_DIR + labelled clips
python -m eval.score_spike eval/reports/<date>
python -m eval.score_cuts                            # detector P/R/F1 vs eval/labels (needs a CLI run per clip)
python -m eval.llm_bench --provider ollama           # LLM verdict accuracy on synthetic sentences (3 runs)
cd frontend && npm run lint && npm test              # tsc + eslint + prettier, then vitest
cd frontend && npm run build
```

## Workflow

1. Every change belongs to a Jira task (`LEARNING-xxx`). If the user gives none, ask for it.
2. Branch: `feature/LEARNING-xxx-short-name` (or `fix/...`, `chore/...`). Never commit directly to `main`.
3. Commits: Conventional Commits with the Jira key, e.g. `feat(rules): detect repeated words LEARNING-207`.
4. Before every commit: lint, type check and tests must pass locally.
5. One task = one PR. The PR description lists what changed, how it was tested, and any deviation from the design.
6. Update README, docstrings and ADRs in the same PR when behaviour or decisions change.
7. Use `.github/pull_request_template.md` for the PR and go through `docs/checklists/pr-review.md`.
8. If a task hits a surprising bug, a wrong assumption or a non-obvious fix, propose a lesson in `docs/lessons/` (from `TEMPLATE.md`) in the same PR.
9. Spikes write their report to `docs/spikes/` (from `TEMPLATE.md`) and end with a decision or ADR.
10. After pushing a branch, open the PR with `gh pr create` using the template, then watch CI with `gh pr checks --watch` and fix failures until green. Never merge; the owner merges.

## Rules you must follow

**Privacy & security**
- Only transcript text goes to the LLM API. Never upload audio, video or file paths.
- Secrets only via `.env` (keep `.env.example` in sync). Never commit keys.
- The API binds to `127.0.0.1` only.

**Architecture boundaries**
- The UI never talks to the worker; everything goes through the API.
- Heavy work (model, FFmpeg) runs only in the worker process, never in the API process.
- Do not add new services, databases, cloud dependencies or a settings UI. If a change seems to need one, stop and propose an ADR in `docs/adr/` instead.

**Cross-platform**
- No hard-coded paths. Use `pathlib` and `platformdirs`.
- Select device and encoder at runtime with fallbacks; never assume `mps` or `videotoolbox`.
- File names may contain spaces and Vietnamese characters; test with them.

**Resources**
- One job at a time. Respect configured limits: thread caps, step timeouts, RAM pre-flight.
- All thresholds live in config, not in code.

**Reliability & observability**
- Every pipeline step records a span (job id, step, duration, status, error).
- Every error path logs with the job id and leaves the job in a clear state (`failed` + `failed_step`). Reviewed cuts are never lost.
- Capture FFmpeg stderr on failure.

**Testing**
- A bug fix starts with a failing test.
- Unit and integration tests use the **fake transcriber** and synthetic media; they must not download models or need network.
- Rule engine coverage stays above 80%.
- Do not tune rules on the held-out golden clips.
- Golden clips (real voices) are private and never committed; only labels and the manifest live in the repo.
